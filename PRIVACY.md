# Privacy

Pinacora has no account system, analytics SDK, advertising, telemetry, or automatic crash reporting in its application code.

## Network requests

The app requests public gallery catalogue and artwork pages from `www.reframed.gallery`, and preview/original images from `cdn.reframed.gallery`, over HTTPS. Requests include a User-Agent and gallery Referer. Those services receive ordinary connection information, including your IP address, and the URLs you request. Their operators control their own logging and privacy practices. The app sends no data to a project-maintainer service. Its background worker accepts commands through a private local Unix socket, with no network listener.

Search sends trimmed queries of at least two characters to Reframed’s gallery search endpoint after a short pause in typing. Refresh and Load more contact the gallery. Selecting artwork can fetch metadata and previews; Set wallpaper downloads its original if it is not already valid in the local cache. View source and the gallery link open your browser, which has its own history and privacy settings. The `--check-source` developer diagnostic also contacts the gallery and downloads one original.

A first entire-gallery start discovers a candidate using catalogue pagination, usually with about three metadata requests, then prepares its original. The full catalogue loads separately in the background. Later starts and resumes use cached metadata immediately and refresh it in the background, with further refreshes at cycle boundaries. It downloads one next original at a time as rotation proceeds. Background catalogue failures keep the usable cached catalogue and retry at a bounded cadence. Selected-artwork rotation downloads the next original in the saved order. Opening rotation settings alone does not load the full catalogue. Pausing or stopping rotation stops further scheduling; an HTTP request already in progress may finish and retain a cached image. Quitting the GUI leaves the background rotation service running. Active rotation resumes at graphical login, and can continue to contact the gallery while the GUI is closed.

The GUI checks `api.github.com` for the latest stable release on startup, every 24 hours while open, and when you request a check. These requests include the app version in its User-Agent; GitHub receives ordinary connection information including your IP address. Only **Update and restart** downloads release assets from GitHub and its release CDN over HTTPS. Update checks do not send gallery searches, preferences or artwork history. See [Updates](docs/updates.md) for verification and local helper files.

## Local data

The app stores preview images in `~/Library/Caches/Pinacora/previews`, originals in `~/Library/Application Support/Pinacora/originals`, and a versioned walkthrough completion/skip preference in `~/Library/Application Support/Pinacora/walkthrough.json`. Rotation stores its versioned source, minute interval, and selected artwork metadata locally in `rotation.json` alongside `walkthrough.json`. A separate versioned `rotation-catalogue.json` stores only confirmed complete catalogue metadata, IDs of successfully shown gallery artworks, and the last shown artwork ID. Before a full catalogue is available, that file may contain history without an inventory. This history survives source changes and reopening; it resets after a known full catalogue cycle is exhausted. Corrupt or unsafe metadata is treated as a cache miss. The background service saves active intent, its deadline, and current wallpaper metadata locally and restores them after restart. It makes at most one change after a missed deadline. Image filenames are hashes of source URLs. There is no automatic cache-size cap or expiry. Rotation can accumulate many retained originals over time; preparing one image ahead does not remove originals from earlier changes. Search text and the Motion setting are not persisted by the app.

On macOS 14 or newer, wallpaper application writes the local original’s file URL into macOS’s local wallpaper store to apply it to all Desktops, then restarts the wallpaper service. The app preserves a separate backup before each change at `~/Library/Application Support/com.apple.wallpaper/Store/Index.plist.pinacora-backup-*`. Automatic rotation creates the same separate backup for every change. These backups retain the previous local wallpaper configuration, including existing file paths, and are not automatically removed. On macOS 12–13 it passes the file URL to the public macOS API for connected displays in the current Desktop. Wallpaper application makes no additional network requests. Removing an original currently in use may affect your wallpaper.

Stop rotation and unload its background service as described in [the README](README.md#remove-background-rotation), then quit the app and use Finder to remove its cache and preference folders if desired. Deleting the app alone does not remove those files. Bug reports, screenshots, and logs that you choose to post on GitHub are subject to GitHub's policies; remove personal information before sharing them.

On Linux, originals, walkthrough preferences, `rotation.json` and `rotation-catalogue.json` use `$XDG_DATA_HOME/pinacora` (default `~/.local/share/pinacora`); previews use `$XDG_CACHE_HOME/pinacora/previews` (default `~/.cache/pinacora/previews`). Relative or empty XDG values are ignored. Wallpaper application passes the retained original's path to local hyprpaper IPC on Hyprland or its file URI to GNOME background settings, without additional network requests. Hyprland changes are limited to the current session and do not edit startup configuration. The local installer writes a binary in `~/.local/bin`, plus a launcher and icon in the user data directory. Remove these files and the storage folders to uninstall and clear local data.

If an existing Reframed directory (macOS) or reframed directory (Linux) exists at a data or cache location, Pinacora continues to use it, independently for data and caches, even if the new directory also exists. It does not migrate or delete files. This preserves walkthrough preferences and original paths used by active wallpapers. Existing `Index.plist.reframed-backup-*` backups are left in place.

Background rotation uses the same local artwork caches as the GUI. A private `service` directory under the app data directory holds its local socket and worker lock. The service stores its versioned runtime state alongside rotation preferences. On Linux, registration writes a user unit in `$XDG_CONFIG_HOME/systemd/user/pinacora-rotation.service`, an XDG login entry in `$XDG_CONFIG_HOME/autostart/pinacora-rotation.desktop`, and graphical session environment data in `$XDG_RUNTIME_DIR/pinacora/rotation-session.env`. `XDG_CONFIG_HOME` defaults to `~/.config`. On macOS, registration writes `~/Library/LaunchAgents/com.pinacora.rotation.plist`. These files run the installed Pinacora executable in background service mode under your own user account. Closing the GUI does not remove them. The background service has no telemetry.
