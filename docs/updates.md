# Updating Pinacora

Pinacora checks GitHub's latest stable release when the app opens and every 24 hours while it stays open. The wallpaper worker does not check for app updates. Use **Check for updates** to check sooner. Failed checks retain an already available update and can be retried. Checking does not download or install the app.

When a newer compatible release is ready, **Update and restart** downloads it and verifies its SHA-256 checksum before extraction. On macOS it also checks the app identity, version, architecture, code signature and pinned release signing certificate. Preview releases and older versions are never installed. A partially published release without the required archive/checksum cannot be installed.

In-app replacement supports `Pinacora.app` in `/Applications` or `~/Applications` on macOS, and the actual executable at `~/.local/bin/pinacora` on Linux x86_64. The installation's parent directory must be writable. Source builds, symlinked Linux executables, system package installations, unsupported architectures and other installation locations require a manual update. Move the macOS app to Applications first if necessary. A worker registration pointing at another installation also requires manual reconciliation before updating.

After verification, a private helper validates its installation and staging paths and signals that it is ready before the GUI closes. If this preflight fails or takes longer than 30 seconds, the GUI stays open with an error. Only one helper can update an installation at a time; a second attempt keeps its GUI open and asks you to retry. The helper rechecks the installed version before replacement so an offer from an older open app cannot overwrite a newer installation. It then waits for the GUI to exit, preserves the old installation, swaps in the new app, refreshes an already loaded/running wallpaper worker and reopens the GUI. It never enables an absent or intentionally unloaded worker, changes rotation preferences or clears artwork caches. If replacement, worker refresh or the relaunch request fails, the helper restores and reopens the previous app. Relaunch acceptance does not prove that the new GUI remains healthy; an operating-system crash after accepted launch is outside this rollback guarantee.

Downloads are limited to 512 MiB and extraction to 1 GiB and 20,000 entries. Archive traversal, links and special files are rejected. No downloaded installer scripts are run.

If the GUI cannot close within 60 seconds, installation is cancelled. Failures after the helper becomes ready are logged in `.pinacora-update-*/update.log` alongside the installed app or binary; the private directory retains staged files for investigation. A failed rollback retains `previous` there for manual recovery. Successful updates remove the helper directory. A small `.pinacora-update.lock` file remains beside the installation to coordinate future updates; it contains no preferences or artwork. Report the log after reviewing it for local paths, and update manually if necessary.

Versions published before this feature need one manual installation of an updater-equipped build. The source version may be ahead of the published stable release; this correctly produces no update offer.
